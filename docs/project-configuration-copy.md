# 项目配置复制

在「设置 → 项目 → 常规」点击「从现有项目复制配置」，选择同一工作空间中有权访问的模板项目。

可分别选择工作流状态和自定义字段，默认都选择。复制前展示模板的状态与字段名称。

- 工作流包含状态名称、顺序、颜色、图标、内部标识和完成标记。仅允许替换没有任何任务（包括归档、计划任务）且没有自动化规则的目标项目。
- 字段包含类型、选项、必填和默认值。新增字段按模板顺序追加；同名且设置一致的字段跳过，同名但设置不同则整次操作失败。
- 新字段的默认值按现有字段创建规则填入目标项目任务。已有字段值保留。
- 不复制任务、评论、工时记录、成员、集成或自动化规则。
- 操作要求目标工作空间的 project:update 权限及两个项目的访问权限。禁止跨空间和自我复制，归档项目不可参与。
- 全部变更使用一个数据库事务，任何失败均回滚。无需数据库结构迁移。

## 验收

1. 空项目一键获取模板的状态和字段，模板不变。
2. 已有任务时禁止勾选工作流，但允许仅复制字段。
3. 同名冲突提示具体字段，保留原配置及任务数据。
4. 重复复制字段不创建重复定义，不覆盖任务值。
5. 无权限、跨空间及受限项目访问均由 API 拒绝。
6. 复制后刷新工作流、字段和看板查询。

## 构建与回退

本功能基于上游 v2.46.2 开发，运行镜像保留该版本的数据库结构和依赖。
部署前备份数据库和 Compose 配置；保留原始镜像和上个 Compose 文件，回退时恢复镜像引用并重建应用容器，无需恢复数据库。

构建使用与上游相同的锁文件，未修改运行时依赖。先编译，再在有 Docker 的环境中打包：

```sh
pnpm install --frozen-lockfile
pnpm --filter @kaneo/api build
pnpm --filter @kaneo/web build
docker build --pull=false -f Dockerfile.custom --build-arg SOURCE_REVISION="$(git rev-parse HEAD)" -t kaneo-custom:2.46.2-copy-config .
```

`Dockerfile.custom.dockerignore` 将上下文限定为编译结果，不包含 `.env`、数据库或账号信息。镜像沿用上游入口脚本，根据部署环境注入 API 地址。

需要重建所有依赖时，仍可使用上游的 `Dockerfile.kaneo`。
